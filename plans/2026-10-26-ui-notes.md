# UI specification

Date: 2026-10-26

Specification for the app's user-facing behaviour, worked out from Takoboto screenshots. Takoboto is the baseline for the basic dictionary UI. Only the features listed here are in scope. Takoboto features not mentioned here are out of scope (favourites, word lists, quizzes, kanji search by radical, the Phrases tab, text-to-speech, sharing, romaji input).

Companion document: `2026-10-26-feature-research.md`, covering how AnkiDroid integration, KanjiVG component breakdown and stroke-practice matching work.

---

## 1. Navigation

- **App-wide back stack.** The top-bar ← and the system back gesture both pop it. Back on the root search screen exits the app.
- **Actions that push a history entry:**
  - Tapping a search result → entry page.
  - Tapping a See also / antonym link → search screen with that text in the field and searched.
  - Tapping a kanji in a component breakdown or "contained in" list → standalone kanji page.
- **Typing in the search field doesn't push.** The search screen updates in place.
- **Each history entry restores its full state:** search query and results scroll position, the selected entry tab, expanded practice areas, scroll position.
  - Returning to a search screen shows its kept results without searching again.
  - The state survives configuration changes (e.g. a dark-mode switch).
- **Keyboard:** whenever a search screen is shown (app start, or returning to it with back), the field is focused with the cursor at the end of its text and the keyboard is up. The one exception: a search screen pushed by a See also link first shows its results with the keyboard down. Opening a result hides the keyboard.
- **Screens:**
  - **Search** (root).
  - **Entry**, with tabs Word / Kanji / Forms.
  - **Kanji page**: a standalone kanji display container (§5) holding a single kanji.
  - **Settings**: a few simple options, such as the AnkiDroid deck (§8). Its full contents and how it's reached aren't defined yet (see `progress.md`, open questions).

## 2. Search screen

### Layout
- **The app opens straight into search,** with the field focused and the keyboard up. There's no home screen.
- **Right end of the search field:**
  - Empty field: a **paste** button that pastes the system clipboard and searches immediately.
  - Non-empty field: a **clear** button.
- Empty state: brief help text (e.g. the wildcard syntax).

### Lookup behaviour
- **Live search:** results update on every change to the field, **including uncommitted IME composition text** (e.g. kana still underlined before kanji conversion).
- **Input kinds:** kanji and kana (typed with a Japanese keyboard), or English. Any input with no Japanese characters is an English search. There's no romaji input: `taberu` searches English glosses.
- **Prefix matching** on written forms and on readings: ゆううつ → ゆううつ, ゆううつしつ, ゆううつしょう. 憂鬱 → 憂鬱, 憂鬱症, 憂鬱質.
- **Wildcard:** `?` matches exactly one Japanese character (`日?`, `??語`).
- **Fuzzy reading match** that tolerates two kinds of slip:
  1. **Long vowels:** an extra or missing う/お/ー extending a vowel (ゆうき ≈ ゆき, おおきい ≈ おきい, コーヒー ≈ コヒー).
  2. **Voicing:** voiced and unvoiced kana are equal (つ/づ, し/じ, か/が, は/ば/ぱ…), which covers rendaku and ず/づ, じ/ぢ.
  - Implementation: each reading has a normalized **fuzzy key** (katakana → hiragana, voicing removed, long-vowel extensions collapsed). The query is normalized the same way.
- **Deinflection:** conjugated input finds the dictionary form, e.g. 掛けた → 掛ける, 引かなかった → 引く, 食べられない → 食べる.
  - Rules are the reverse of the conjugation engine (§6), checked against the candidate's JMdict POS. Yomitan's deinflection rules are the reference.
  - A deinflected result shows the inflections it undid, in English, using the Forms tab row names, outermost last (e.g. "past, negative" for 引かなかった). Inflections chain: 食べられない undoes a negative, then a potential or passive.
  - When a form is ambiguous, the label lists the possible readings joined with " or " (食べられる → "potential or passive").
- **Ranking:**
  1. Exact match.
  2. Whole-word fuzzy match: the query's fuzzy key equals a reading's fuzzy key (ゆき finds 勇気 ゆうき here, above the many words starting with ゆき).
  3. Deinflected match.
  4. Prefix match.
  5. Fuzzy prefix match.

  Within each tier, common words, then higher JPDB frequency, rank first.
- **English search** matches glosses, in three tiers:
  1. A whole gloss equals the query (ignoring a leading "to"/"a"/"the" and parentheticals, so "eat" matches "to eat").
  2. A whole gloss starts with the query.
  3. A gloss contains the query as a word.

  Within each tier, a match in an entry's first sense outranks a match in a later sense, then common words, then frequency.

### Result rows
- **First line:** all written forms and readings, comma-separated.
  - **The form or reading that matched is highlighted** (accent colour). For a prefix match, the unmatched remainder is a slightly different shade. This highlight is how the user sees which spelling was hit (e.g. 掛ける vs 懸ける), and the matched form is carried into the entry page, Copy, and Send to AnkiDroid.
  - **Rare or irregular forms are greyed out:** kanji tags `rK`, `iK`, `oK`, `sK`; reading tags `ik`, `ok`.
  - **Pitch accent** is drawn on readings (§7).
- **Second line:** glosses, comma-joined. Multiple senses are numbered and collapsible.
- **Badges:** "common" (any form carries JMdict priority `news1`, `ichi1`, `spec1`, `spec2` or `gai1`; jmdict-simplified's `common` flag) and する (POS `vs`).

### Interaction
- **Tap** → entry page for that entry, keeping the matched form.
- **Headword** (the "matched form" carried into the entry page, Copy and Send to AnkiDroid):
  - A matched written form is the headword.
  - A matched reading is the headword if the entry has no written forms or its first sense is tagged `uk`. Otherwise the headword is the first written form that reading applies to, skipping rare/irregular forms when possible.
  - With no form match (English search): the first written form, or the first reading for kana-only and `uk` words.
- **Long-press** → a small menu anchored to the row, with:
  - **Copy:** copies the matched form (e.g. 憂鬱). If the match was on a reading of a kana-only word, it copies that reading.
  - **Send to AnkiDroid:** creates a Kaishi 1.5k note (§8). Shows a confirmation, or an "open in AnkiDroid" action if the note already exists.

## 3. Entry page: header and tabs

- **Top bar:** ← back, then the headword (§2).
- **Tabs:**
  - **Word.**
  - **Kanji:** shown when any written form contains kanji.
  - **Forms:** shown when the entry has a POS that conjugates.

## 4. Word tab

Top to bottom:
1. **Matched written form**, large.
2. **Other written forms**, large (all written forms when the headword is a reading). Rare or irregular forms are greyed out, with their tag spelled out beneath (e.g. "rarely-used kanji form" for `rK`).
3. **Reading(s), with pitch accent** (§7). This is important. Each reading has its own pitch, and a reading with several accent patterns shows all of them side by side. Rare readings are greyed with their tag spelled out, like written forms.
4. **Meaning:**
   - **Senses are grouped by part of speech.** Senses with the same set of POS codes form one group, and groups appear in order of their first sense. Each group has a header with the POS and misc tags common to all its senses, in **Japanese only** (e.g. 一段動詞・他動詞). No English names and no romaji. Misc tags such as `uk` (usually written in kana) also get short Japanese labels. All labels come from one complete JMdict-code → Japanese table (§9).
     - Example: 立てる has senses 1–26 under 一段動詞・他動詞, then sense 27 under 接尾辞・一段動詞.
     - When every sense has the same POS, there's a single header.
     - A noun that takes する folds `vs` into its transitivity label: n + `vs` + `vt` → 名詞・他動詞（する）, and likewise 自動詞（する）. `vs` without `vt`/`vi` shows as する動詞.
   - **Numbered senses** (no number when there's only one). Senses keep their JMdict numbers inside the groups, so a gap (1, 2, 4) shows that the missing sense is in a later group. Each sense shows its English glosses (comma-joined) plus only what's specific to it: field/dialect/misc tags not in the group header (Japanese labels), JMdict's sense notes (`info`), and cross-references.
   - **See also / antonym links** (JMdict `related` / `antonym`) are tappable. A tap pushes the search screen with that text searched (§1).
     - jmdict-simplified cross-refs are `[kanji, kana?, senseIndex?]` or `[kana, senseIndex?]`. Display the words joined with ・ and the sense number in parentheses, e.g. でしょう (1). Search for the first element.

The Word tab doesn't show monolingual Japanese definitions.

## 5. Kanji tab and kanji pages

### Kanji display container
A reusable component that shows **any number of kanji, stacked vertically**, one block each. The Kanji tab is this container filled from the current entry. A standalone kanji page is this container holding one kanji.

### Which kanji (Kanji tab)
Every kanji from every written form of the entry, deduplicated, in this order:
1. The matched form first, then the remaining written forms in JMdict order, with rare/irregular forms (`rK`, `iK`, `oK`, `sK`) last.
2. Within a form, left to right.
3. A kanji that's already listed keeps its first position.

Examples: 憂鬱 → 憂, 鬱, 幽, 悒. 懸ける (matched) → 懸, 掛.

### Kanji block
Top to bottom (vertical scrolling is fine):
1. **Header row:**
   - A large kanji tile.
   - Beside it: ON readings (katakana), KUN readings (hiragana, with KANJIDIC2's `.` okurigana marker, e.g. か.ける), and English meanings.
   - Below: stroke count, JLPT level, school grade.
   - **On the Kanji tab, the KUN/ON reading this word uses is highlighted**, using JmdictFurigana's per-kanji alignment. Standalone kanji pages have no word context and no highlight.
2. **Practice area:** full-width and **collapsed by default** behind a "Practice" button. When expanded, a square drawing canvas at the full content width sits directly below the header row, so the kanji and the canvas are on one screen.
   - Controls: Hint, Show Me, Clear.
   - Matching algorithm: research doc §3.
3. **Component breakdown:** a recursive tree from KanjiVG element groups. Each node shows the component, its meaning and readings (where KANJIDIC2 has them), and is tappable (→ kanji page). The phonetic component (`kvg:phon`) is marked. Research doc §2.
4. **Contained in:** more complex single kanji that use this kanji as a component (reverse KanjiVG lookup, e.g. 昜 → 陽 場 湯 腸 傷). Each one is tappable (→ kanji page). Sorted by frequency/grade. Long lists show a first batch and a "more" control.

## 6. Forms tab

A compact conjugation **table** in the style of jisho.org: rows are inflections, and columns are **Affirmative** and **Negative**. There's no pitch accent and there are no per-form English glosses.

- **Title:** the conjugation class in Japanese, matching the POS labels (e.g. 五段動詞（く）, 一段動詞, サ変動詞).
- **Forms are spelled with the matched written form** (掛けた, not かけた). Entries tagged `uk` use kana.
- **Row labels are in English.**
- **An entry with several conjugating POS classes** (e.g. both `v5r` and `v1`) shows one table per class, each under its own title.
- Long forms wrap within their cell.

### Verb rows (all inflections)

Example: 引く.

| Row | Affirmative | Negative |
|---|---|---|
| Non-past | 引く | 引かない |
| Non-past, polite | 引きます | 引きません |
| Past | 引いた | 引かなかった |
| Past, polite | 引きました | 引きませんでした |
| Te-form | 引いて | 引かないで, 引かなくて |
| Progressive | 引いている | 引いていない |
| Progressive, polite | 引いています | 引いていません |
| Volitional | 引こう | 引くまい |
| Volitional, polite | 引きましょう | — |
| Desiderative | 引きたい | 引きたくない |
| Conditional (ば) | 引けば | 引かなければ |
| Conditional (たら) | 引いたら | 引かなかったら |
| Alternative (たり) | 引いたり | 引かなかったり |
| Potential | 引ける | 引けない |
| Passive | 引かれる | 引かれない |
| Causative | 引かせる | 引かせない |
| Causative passive | 引かせられる, 引かされる | 引かせられない, 引かされない |
| Imperative | 引け | 引くな |
| Request | 引いてください | 引かないでください |
| Stem (連用形) | 引き | — |

### Adjective rows

| Row | Affirmative | Negative |
|---|---|---|
| Non-past | 高い | 高くない |
| Non-past, polite | 高いです | 高くないです, 高くありません |
| Past | 高かった | 高くなかった |
| Past, polite | 高かったです | 高くなかったです |
| Te-form | 高くて | 高くなくて |
| Adverbial | 高く | — |
| Conditional (ば) | 高ければ | 高くなければ |
| Conditional (たら) | 高かったら | 高くなかったら |

### Conjugation engine
The table is generated by rules keyed on the JMdict POS code. Nothing is stored. The same rules, reversed, drive deinflection search (§2).
- `v1`: ichidan.
- `v5u`, `v5k`, `v5g`, `v5s`, `v5t`, `v5n`, `v5b`, `v5m`, `v5r`: godan.
- Godan exceptions: `v5k-s` (行く: 行った, 行って), `v5r-i` (ある: negative ない), `v5aru` (ござる, くださる…: imperative 〜い), `v5u-s` (問う: 問うた).
- `vk` (来る), `vs-i` / `vs-s` (する and 〜する). Nouns with `vs` (勉強) show the 勉強する forms.
- `adj-i`, and `adj-ix` (いい/良い → よくない…).

## 7. Pitch accent display

- **Data:** Wadoku pitch database (see §9).
- **Rendering:**
  - Split the reading into morae (small ゃゅょぁぃぅぇぉゎ attach to the preceding kana).
  - Draw an overline across each run of high morae.
  - Draw a right-edge downstep tick (⌝) where a high mora is followed by a low one.
  - Flat (平板) words have an overline to the end with no tick. 尾高 words, whose drop falls on the following particle (Wadoku's trailing letter is L after a final H), have an overline to the end with a tick. This tick is display-only: the Pitch Accent field sent to Anki (§8) stays identical to `pitch_accent_renderer.rb`, which ignores the particle letter.
  - Each mora's pitch is the uppercase letter among its characters' letters, as in `pitch_accent_renderer.rb`.
  - The overline sits just above the kana, clearing dakuten, measured from the text baseline.

  This is drawn natively in Compose, following the same logic as `../anki-scripts/lib/pitch_accent_renderer.rb`.
- **Where it appears:** search result rows (each reading's first pattern) and the Word tab (all patterns). Not on the Forms tab.
- **Lookup:** for each reading, try (headword, reading), then each other written form the reading applies to, then (reading, reading) for kana words.

## 8. Send to AnkiDroid

- **Transport:** the AnkiDroid ContentProvider API (`AddContentApi`) with the `com.ichi2.anki.permission.READ_WRITE_DATABASE` runtime permission. Research doc §1.
- **Note type:** **Kaishi 1.5k**, the user's existing card format. Its 14 fields are: Word, Word Reading, Word Meaning, Word Furigana, Word Audio, Sentence, Sentence Meaning, Sentence Furigana, Sentence Audio, Notes, Pitch Accent, Pitch Accent Notes, Frequency, Picture.
- **Fields the app fills from its own data:**

  | Field | Content |
  |---|---|
  | Word | the matched written form |
  | Word Reading | the reading |
  | Word Meaning | English glosses |
  | Word Furigana | Anki `漢字[かんじ]` syntax, from JmdictFurigana |
  | Pitch Accent | Kaishi pitch HTML, identical to `pitch_accent_renderer.rb` output |
  | Notes | Japanese grammar labels joined with `、` (same rules as `add-jmdict-grammar-notes.rb`) |
  | Frequency | JPDB rank |

- **Tags:** the anki-scripts "done" tags for the fields filled above: `generated::pitch-accent` (or `pitch-accent::unavailable` when Wadoku has no entry) and `generated::grammar`. The user's anki-scripts then add only sentences, sentence furigana and audio.
- **Formats must match anki-scripts output exactly** (meaning joins, Frequency format, furigana syntax). Read the scripts before implementing.
- **Duplicate check:** same (word, reading) key as `../anki-scripts/lib/dedup_checker.rb`.
- **Deck:** chosen on the settings screen (§1).

## 9. Data sources

| Dataset | Used for | Notes |
|---|---|---|
| JMdict (jmdict-simplified JSON, English) | entries, forms, readings, senses, tags, cross-refs | the same distribution anki-scripts uses |
| KANJIDIC2 | kanji readings, meanings, stroke count, grade, JLPT | |
| KanjiVG | component trees (both directions), stroke paths for practice | |
| Wadoku pitch DB (IllDepence `anki_add_pitch_plugin` extract) | pitch accent | format below |
| JmdictFurigana | per-kanji reading alignment | Word Furigana field; Kanji tab reading highlight |
| JPDB v2 frequency list | ranking, Frequency field | the same list anki-scripts uses |

**Wadoku pitch DB format:**
- One line per entry: `orthographies␞reading␞accent notation␞pattern number(s)␞H/L string`, with orthographies separated by `␟`.
  - Example: `憂鬱␟幽鬱␟…␞ゆううつ␞ゆう'うつ␞0␞LHHHH`.
- The H/L string is **per character**: lowercase marks small kana, and there may be one trailing letter for a following particle. Multiple patterns are comma-separated.
- Look up by (written form, reading). Fall back to the written form alone only when no reading is known.

**Japanese grammar labels:** `pipeline/grammar_labels.tsv` maps every JMdict tag code (POS, misc, field, dialect and form tags) to a Japanese label, e.g. `v1` 一段動詞, `v5k` 五段動詞（く）, `vs` する動詞, `vs-i` サ変動詞, `uk` かな書き, `ksb` 関西弁. The pipeline stores it as `tags.label_ja` and fails if JMdict has a code without a label. The Word tab and Forms tab titles use these labels.

The Anki Notes field (§8) is different: it follows the combining rules in `../anki-scripts/add-jmdict-grammar-notes.rb` (e.g. n + `vs` + `vt` → 他動詞（する）), not one label per code.

**Database (SQLite, built offline by `pipeline/` and shipped with the app):**
- `pipeline/README.md` and `pipeline/lib/schema.sql` describe the built tables:
  - entries as compact JSON;
  - Japanese search keys (kana-folded forms and readings, fuzzy reading keys), each recording which form or reading it came from;
  - English gloss keys;
  - frequency and pitch keyed by (form, reading);
  - furigana alignment;
  - JMdict tag descriptions and Japanese labels.
- Still to be added: KANJIDIC2 kanji data, and a KanjiVG component table (parent → child, position, radical/phonetic flags) indexed in both directions, with per-stroke paths.
